# Specification

## 1. Summary
Implement account-based login lockout after consecutive failed login attempts to slow automated password guessing.

## 2. Goals
- Temporarily lock an account after repeated failed logins.
- Allow successful login to reset the failed-attempt count.
- Prevent authentication while an account is locked.
- Avoid revealing account existence or lockout status in the user-facing error message.
- Allow support staff to manually unlock accounts.

## 3. Functional Requirements
- **FR-1:** After 5 consecutive failed login attempts for an account, the account must be locked for 15 minutes.
- **FR-2:** A successful login must reset that account’s failed-attempt count to zero.
- **FR-3:** Login attempts for a locked account must be rejected, even when the submitted password is correct.
- **FR-4:** The user-facing error message must not reveal whether the account exists or is locked.
- **FR-5:** Support staff must be able to manually unlock an account.
- **FR-6:** Lockout must be applied per account, not per IP address.

## 4. Acceptance Criteria

### FR-1
**Given** an account has fewer than 5 consecutive failed login attempts  
**When** a login attempt fails and brings the consecutive total to 5  
**Then** the account is locked for 15 minutes.

### FR-2
**Given** an account has a failed-attempt count above zero  
**When** that account logs in successfully  
**Then** its failed-attempt count is reset to zero.

### FR-3
**Given** an account is locked  
**When** a login is attempted with the correct password  
**Then** the login is rejected.

### FR-4
**Given** a login attempt results in an error  
**When** the user is shown the error message  
**Then** the message does not reveal whether the account exists or is locked.

### FR-5
**Given** support staff need to unlock an account  
**When** they manually unlock it  
**Then** the account is no longer locked.

### FR-6
**Given** login attempts are made for an account from one or more IP addresses  
**When** failed attempts are counted  
**Then** the lockout threshold is determined per account, not per IP address.

## 5. Out of Scope
- Password reset flow.
- Multi-factor authentication.

## 6. Assumptions
- “Consecutive” failed attempts refers to attempts for the same account since the last successful login.
- The 15-minute lockout begins when the fifth consecutive failed attempt occurs.

## 7. Open Questions
- Should failed attempts made while an account is already locked affect its failed-attempt count?
- What should happen to the failed-attempt count after the 15-minute lockout expires?
- What authentication or authorization controls should govern manual unlocks by support staff?
